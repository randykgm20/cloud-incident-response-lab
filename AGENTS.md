# Working on this lab

- Teach before major changes. Explain what is happening, why it matters, what each command does, and what results to expect. Define technical terms and acronyms on first use.
- Work inside the authorized repository and its local test environment. Use synthetic data. Keep secrets, credentials, personal data, military information, and operational details out of the project.
- Obtain explicit approval before connecting to external systems or creating cloud resources. Flag actions that could incur costs or expose data before they happen.
- Prefer small changes that a beginner can explain. Explain important security decisions.
- Write tests for new behavior and run the full test suite before claiming completion.
- Keep the documentation synchronized with the code. Record measured achievements in `docs/resume-evidence.md`.
- Preserve raw evidence and retain a reason for tuned findings. Test rule/config validation and failures that could overwrite or misrepresent inputs.
- Keep this portfolio local and synthetic. Obtain explicit approval before commits, external publication, live integration, deployment, or response actions.
