# Learning notes

Each example comes from this local lab. Practice saying the last part of each row in your own words.

| Concept | Definition and why it matters | Lab example | Common mistake | Interview explanation |
| --- | --- | --- | --- | --- |
| CloudTrail | An Amazon Web Services (AWS) service that records account and service activity. The record helps an analyst reconstruct what happened. | A `StopLogging` event names the trail affected by a change. | Assuming one trail records every category of activity automatically. | “I used CloudTrail-style records to reconstruct activity from the actor, timestamp, action, and request parameters.” |
| API event | An application programming interface (API) lets software request an operation. An API event records details about one request and sometimes its outcome. | `CreatePolicy` records a request to create a policy. | Treating a logged request as successful without checking the outcome. | “I pair the service and operation name with the recorded error code and request fields.” |
| Identity and Access Management (IAM) | The service for defining identities and controlling what they can do. It matters because attackers may seek broader permission after gaining an account. | `AttachUserPolicy` records who requested a policy attachment and which user received it. | Assuming a created policy is already attached or fully effective. | “I distinguish creating a policy from granting it to an identity, and check effective access during investigation.” |
| Detection rule | An explicit test for a pattern in one or more records. It turns a large set of events into a smaller set of leads. | Three failed console sign-ins for one identity within ten minutes produce one finding. | Counting duplicate records as different attempts. | “I tested the threshold, time window, identity grouping, and a normal control.” |
| Indicator of compromise (IOC) | An observable artifact associated with a compromise. An indicator helps an analyst search for related activity, and its reliability depends on context. | An Internet Protocol (IP) address absent from the lab baseline is a lead. Additional evidence would be needed to establish that it is an IOC. | Labeling every unfamiliar address as an IOC. | “I can use an address as a search pivot and corroborate it with account activity before assigning significance.” |
| Severity | The rule's estimate of how urgently a finding merits review. It helps an analyst prioritize the queue. | Stopped logging is high severity because a gap can impair investigation. | Confusing urgency with confidence that an incident happened. | “Severity reflects possible impact. I still check the evidence and expected changes.” |
| False positive | A rule match explained by legitimate activity. Recognizing these helps improve signal quality. | An approved remote connection from a new address could trigger the source rule. | Suppressing all future unfamiliar addresses after one benign event. | “I confirm the explanation, measure recurring noise, and narrow the rule or baseline with tests.” |
| Incident response | The work of investigating, containing, and recovering from a security incident. Evidence supports both analysis and later review. | The report suggests reviewing coverage and the last available event when logging stops. | Changing a configuration before documenting the change and preserving evidence. | “The Phase 1 detector hands analysts evidence and a next step. An analyst decides whether response is warranted.” |
| MITRE ATT&CK | MITRE's Adversarial Tactics, Techniques, and Common Knowledge framework describes adversary objectives and behaviors. Tactics describe objectives and techniques describe how an adversary may pursue them. | Repeated failures can support a Password Guessing hypothesis, technique `T1110.001`. | Assigning a technique based solely on a weak indicator or marking a hypothesis as confirmed. | “I mapped behaviors with a clear connection and left weak or ambiguous matches unmapped.” |
| Structured logging | Logging with named fields in a consistent format. This helps tools query, sort, and compare records. | JavaScript Object Notation (JSON) fields include `eventID`, `eventTime`, and `eventName`. | Searching only for a word like ‘failed’ in raw text. | “I use named fields to correlate records and keep the original objects for evidence.” |

## Concepts added in the final portfolio update

| Concept | Definition and why it matters | Project example | Common mistake | Interview explanation |
| --- | --- | --- | --- | --- |
| Detection-as-code | Storing detection intent and configuration in reviewable files with tests. It supports repeatable review and change tracking. | A JSON rule contains selectors, severity, and investigation guidance. | Assuming schema validation proves the detection is useful. | “I test rule meaning against both suspicious and harmless examples.” |
| Sigma-style subset | A limited schema borrowing familiar Sigma detection fields. Sigma is an open log-rule format. | A named repeated-failure condition takes a threshold and time window. | Expecting official Sigma syntax or conversion to work without support. | “I documented exactly which fields and conditions the engine supports.” |
| False-positive tuning | Adjusting analysis for activity confirmed to be expected. It helps analysts focus on unresolved leads. | An exact identity/address approval records two suppressions and leaves other findings active. | Approving an entire identity because one event was harmless. | “I keep the rule narrow and preserve the approval reason and evidence.” |
| Threat hunting | Asking a security question and investigating records to assess it. It develops reasoning beyond alerts. | A success follows three failures in the hunting timeline. | Treating the detector's output as a complete incident narrative. | “I separate facts, interpretations, and assumptions and request missing evidence.” |
| Deterministic evaluation | Identical event sets, rules, and settings give identical results. It makes debugging and review repeatable. | Equal-time findings use event and rule identifiers as tie breakers. | Relying on file arrival order. | “I sort before correlation and use stable report ordering.” |
| Regression test | A test that catches a previously missing or incorrect behavior. It helps prevent a later change from reintroducing it. | A report destination cannot replace a rule or config input. | Testing only the message and ignoring the resulting files. | “I reproduce the failure and verify both the outcome and preserved state.” |
| Atomic replacement and rollback | Replacement exposes one complete file at a time. Rollback restores an earlier state after a recoverable error. | A failed Markdown publication restores the prior JSON report. | Assuming a two-file update is crash-safe because each replacement is atomic. | “I tested recoverable failures and documented power-loss and concurrency limits.” |
